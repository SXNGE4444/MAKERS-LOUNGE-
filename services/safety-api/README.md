# Travel Safe Safety Intelligence API

PocketBase backend for the Travel Safe South Africa web app.

## What this service does

- serves privacy-reduced incident points for map overlays;
- aggregates recent incidents into zoom-aware heat-map cells;
- exposes official or partner aggregate crime statistics with provenance;
- exposes confidence-aware area safety scores from validated snapshots;
- keeps source type, freshness and reliability visible to the frontend.

The API deliberately does not label a place "safe" or "unsafe" as an absolute fact. A score is a comparative planning signal and every score includes confidence and provenance.

## Local run

Download the current PocketBase binary for your platform and place it in this directory, then run:

    ./pocketbase serve

PocketBase automatically runs migrations from pb_migrations and loads routes from pb_hooks.

Health check:

    curl http://127.0.0.1:8090/api/travel-safe/v1/health

Example heat-map request:

    curl "http://127.0.0.1:8090/api/travel-safe/v1/heatmap?bbox=18.35,-34.05,18.65,-33.80&zoom=12&hours=720"

## Collections

- data_sources — provenance, licensing, freshness and source reliability.
- areas — stable area identifiers and optional geometry or centroids.
- crime_stats — aggregate period statistics such as station or municipality category counts and rates.
- incidents — point events; built-in collection access is locked and public routes sanitize coordinates.
- area_safety_snapshots — versioned derived scores generated by an ingestion or scoring job.

Built-in collection APIs are intentionally superuser-only. Public clients use the custom /api/travel-safe/v1 routes.

## Frontend contract

The canonical contract is contracts/safety-api.openapi.yaml.

A synthetic heat-map fixture is available at contracts/fixtures/travel-safe/heatmap.demo.json.

The fixture is fabricated and must never be shown as real crime data.

## Fly.io

PocketBase uses SQLite, so pb_data must live on a persistent Fly Volume. Start with one Machine in Johannesburg (jnb) because a Fly Volume is tied to one Machine and region.

From this directory:

    cp fly.toml.example fly.toml
    fly launch --no-deploy
    fly volumes create pb_data --region jnb --size 1
    fly deploy

After deployment, smoke-test the exact production URL:

    curl https://YOUR-APP.fly.dev/api/travel-safe/v1/health

Do not add a second writable PocketBase Machine against the same volume. If the product outgrows the single-writer SQLite model, migrate the analytical or geospatial workload deliberately rather than pretending horizontal writes are safe.

## Production data rules

1. Never fabricate live crime statistics.
2. Keep official statistics separate from community reports.
3. Store source URL, authority, period and import time.
4. Deduplicate external incident IDs before scoring.
5. Public point data is rounded to reduce location precision.
6. Do not expose victim identity or sensitive free text.
7. A missing or weak dataset returns insufficient_data; it does not generate a fake score.
8. Synthetic records must remain excluded in production.
